# internal/* package docs

One doc per top-level Go package under `internal/`, each with a short description, key types/functions, and a mermaid dataflow diagram — generated by reading the actual source, not the ticket specs. Subpackages (e.g. `internal/resolver/golang`, `internal/data/chunk/markdown`) are covered as subsections of their parent's doc rather than as separate files.

For the full shipped-behavior narrative and per-command sequence diagrams, see [docs/architecture.md](../architecture.md). These docs are package-scoped and code-first; architecture.md is command-scoped and ticket-first — read both together when in doubt.

## Bootstrap / shared

- [config](config.md) — `Config` struct, defaults, YAML load/save/validate, OS-specific path resolution.
- [domain](domain.md) — core shared types (`Project`, `Dependency`, `KnowledgeObject`, `Chunk`, `Generation`, ...) and the two lifecycle state machines.
- [executil](executil.md) — the one subprocess-execution helper every resolver/git call uses.

## Discovery and resolution

- [project](project.md) — directory scanning and stable project IDs.
- [resolver](resolver.md) — the `Resolver` interface plus the `golang`/`python`/`node` implementations.
- [registry](registry.md) — knowledge-package manifests: schema validation, loading/merging, matching.

## Acquisition and normalization

- [source-git](source-git.md) — git mirror cache, worktree materialization, commit deltas.
- [normalize](normalize.md) — the `Normalizer` interface plus `markdown`/`plaintext`/`godoc`/`releasenotes`.

## Content identity, chunking, storage

- [data-fingerprint](data-fingerprint.md) — content-identity hashing and object IDs.
- [data-chunk](data-chunk.md) — the `Chunker` interface plus `markdown`/`symbol` chunkers.
- [control](control.md) — `internal/control/bbolt`, the control-plane store (projects, resolutions, generations, references, replicas).
- [data-badger](data-badger.md) — `internal/data/badger`, the data-plane store (knowledge objects, chunks, manifests).

## Pipeline orchestration

- [data-generation](data-generation.md) — `Create`/`Build`/`Replicate`: the end-to-end ACQUIRING → NORMALIZING → INDEXING → replication pipeline.
- [embedding](embedding.md) — the `Embedder` interface plus the `ollama` client and the `cache` wrapper.
- [backend](backend.md) — the `VectorBackend` interface plus the `qdrant` adapter and the in-memory test fake.
- [planner](planner.md) — diffs a project's resolution against stored state to produce sync actions.
- [lifecycle](lifecycle.md) — `validate` (structural/sanity/live smoke-test checks) and `promote`, plus `gc`.
- [retention](retention.md) — reference counting and grace-period GC planning.

## Serving

- [query](query.md) — vector search over a project's active generation.
- [mcp](mcp.md) — the MCP server exposing query/registry tools to agents.

## CLI

- [cli](cli.md) — the Cobra command tree and how each command wires the packages above together.
