# Epic: Cutting duplicate/oversized dependency acquisition cost

**Status: done** — all four tickets (GIT-004..007) verified done against `docs/architecture.md`.

`internal/source/git`'s `Cache` always does its own full `git clone --mirror` into depctl's own data dir (`<data-dir>/git`), completely independent of whatever the user's own package manager already downloaded (`$GOPATH/pkg/mod`, `site-packages`, `node_modules`), and regardless of the fact that depctl only ever reads a small, documentation-shaped subset of any repo's files. Every project depctl scans pays for a second, full-history, full-tree clone of every dependency, most of which is never read.

This is a real cost, not an oversight — raised directly by the project's own user during the WATCH epic's MCP-bootstrapping follow-up (see `docs/scratch/mcp-bootstrapping.md` for the related gap it was raised alongside). Two complementary strategies apply to the same underlying problem, from different angles — skip fetching when it's already available locally (GIT-004), vs. never fetch more than what's actually read in the first place (GIT-005, generally the stronger win since it applies to every clone, not just ones with a local-cache hit). Originally deferred pending real usage evidence of the actual cost — that evidence arrived: a clean-start sync of depctl's own real, 115-dependency repo took 14+ minutes with zero dependencies completed and 828MB already cloned, and the same root cause (full, non-sparse clones) contributed to a separate live MCP-timeout finding (WATCH-018) on a project depending on a single sizable library. Epic moved from `backlog/` to `planned/` on that basis; see `docs/scratch/embedding-provider-lock-in.md` for the same "profile before optimizing" reasoning applied to a different, still-deferred gap from the same session.

## Tickets

- [GIT-004](GIT-004-local-cache-fast-path.md) (done) — detect an existing local package-manager cache for a resolved dependency and seed/skip the mirror clone from it when found, falling back to the existing clone path otherwise. Go/Python via each ecosystem's own machine-global cache (`GOMODCACHE`, active `python3`'s `site-packages`); Node via the *specific project whose sync action triggered the build*'s own `node_modules` (threaded through as a new `projectRoot` parameter — `domain.Generation` itself still carries no project reference). Measured: 23.5x speedup for a real dependency already in `$GOMODCACHE`.
- [GIT-005](GIT-005-partial-clone-sparse-checkout.md) (done) — blobless partial clone (`--filter=blob:none`) plus sparse-checkout scoped to the file patterns depctl's own normalizers already read, so a clone only ever transfers the doc-shaped content depctl actually uses, without losing the full history cross-version diffing needs.
- [GIT-006](GIT-006-external-mirror-search-path.md) (done) — an optional, explicitly-configured list of external directories `EnsureMirror` checks (in depctl's own `<host>/<org>/<repo>.git` mirror layout) before ever hitting the network — for a pre-cloned mirror set depctl didn't put there itself (a backup/USB drive, another machine's cache), distinct from both GIT-004 (ecosystem-native caches, standard discovery, no config) and from `hack/fetch-corpus`'s default `-mirror-root` (already depctl's own cache, already reused automatically today with no new code).
- [GIT-007](GIT-007-external-checkout-search-path.md) (done) — a sibling fallback tier to GIT-006, for the case an external directory *isn't* laid out in depctl's own mirror convention at all: an arbitrary tree of real git working-tree checkouts (e.g. a personal corpus like `~/offline-knowledge`), discovered by walking the configured root(s) and matching each checkout's own `origin` remote against the dependency's URL, rather than by path convention. Deliberately split out from GIT-006 rather than expanding its scope. Found and fixed a real bug live via its own required real-world measurement: `splitGitURL` didn't normalize a trailing `.git` suffix, so two equally common forms of the same repository URL didn't compare equal — every synthetic test fixture happened to mask it by using identical literal strings on both sides. Measured after the fix: 2.5x speedup against a real `~/offline-knowledge` checkout.

## Non-goals

- No changes to `internal/source/git`'s cache being the source of truth for anything version-history-dependent (release notes, cross-version diffing) — a local package cache only ever accelerates the "get this one version's current source" case.
- No new config surface for GIT-004 specifically — it uses the well-known default locations (`GOPATH`/`GOMODCACHE`, `pip`'s cache dir, `node_modules` relative to the scanned project) each ecosystem's tooling already publishes an env var or command for (`go env GOMODCACHE`, etc.), not a user-maintained list. This doesn't extend to GIT-006/GIT-007: an arbitrary external backup/corpus directory has no standard discovery mechanism at all, so a config key is the correct, minimal design for those two specifically — see each ticket's own reasoning.
- No behavior change for ecosystems without a well-defined shared cache convention (arbitrary `pip install` targets, `node_modules` per-project rather than global) beyond the one obvious win (a scanned project's own `node_modules`/`site-packages`, already right there).
