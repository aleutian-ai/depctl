# ragctl — Completed Tickets

Epics whose every ticket is fully shipped: `**Status:** done` in every ticket file, every Acceptance Criteria box checked, and cross-verified against `docs/architecture.md` (which remains the authoritative "what's actually implemented" narrative — this directory just mirrors that verdict at the ticket-tracking level). See [../planned/README.md](../planned/README.md) for the v0.1 critical-path epics still in progress, and [../backlog/README.md](../backlog/README.md) for deferred scope.

An epic moves here only when **every** ticket inside it is done — a mixed epic (some tickets shipped, some genuinely gapped) stays in `planned/` until that's no longer true. Closing a ticket here doesn't always mean the original sketch got built literally: `CORE-001` and `STORE-001` (below) closed by *reconciling* the ticket to a better shape later epics actually proved out, not by building two now-superseded types just to make an old checklist green. See their own Post-implementation notes for the reasoning — that distinction ("ticket incomplete" vs. "spec drift from real implementation experience") is worth preserving, not collapsing into a flat done/not-done state.

GIT-004 adds a local-cache fast path: Go/Python via each ecosystem's own machine-global cache (`go env GOMODCACHE`; the active `python3`'s `site-packages`, matched via `dist-info`'s own `top_level.txt`, never a name-based guess), Node via the *specific project whose sync action triggered the build*'s own `node_modules` (threaded through as a new `projectRoot` parameter, since `domain.Generation` itself deliberately carries no project reference) — measured, a real dependency already in `$GOMODCACHE`: 23.5x speedup. GIT-006 adds an optional external-directory search laid out in ragctl's own exact mirror convention (a backup of another machine's cache); GIT-007, split out as its own ticket rather than expanding GIT-006's scope, adds a second search tier for an arbitrary directory of real git working-tree checkouts (e.g. a personal `~/offline-knowledge` corpus), matched by each checkout's own `origin` remote instead of path convention. GIT-007's own required real-world measurement caught a real bug every synthetic test had masked: `splitGitURL` never normalized a trailing `.git` suffix, so two equally common forms of the same repository URL didn't compare equal — fixed at the root (moved into `splitGitURL` itself, not patched at the one call site that happened to find it) rather than patched narrowly. Measured after the fix: 2.5x speedup against a real `~/offline-knowledge` checkout.

Real corrections found while implementing, not assumed from the original tickets: Mem0's real endpoint is `POST /v3/memories/add/` (not `/v1/...`) and is asynchronous by default (fixed with `infer: false`); Cognee's `/add` is multipart file upload, not JSON; none of the three services has a dedicated health endpoint, so each `Health()` check uses a real, cheap, read-only endpoint instead. See `LETTA-001`'s own ticket for the full evidence trail.
