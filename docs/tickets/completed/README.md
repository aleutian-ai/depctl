# ragctl — Completed Tickets

Epics whose every ticket is fully shipped: `**Status:** done` in every ticket file, every Acceptance Criteria box checked, and cross-verified against `docs/architecture.md` (which remains the authoritative "what's actually implemented" narrative — this directory just mirrors that verdict at the ticket-tracking level). See [../planned/README.md](../planned/README.md) for the v0.1 critical-path epics still in progress, and [../backlog/README.md](../backlog/README.md) for deferred scope.

An epic moves here only when **every** ticket inside it is done — a mixed epic (some tickets shipped, some genuinely gapped) stays in `planned/` until that's no longer true. Closing a ticket here doesn't always mean the original sketch got built literally: `CORE-001` and `STORE-001` (below) closed by *reconciling* the ticket to a better shape later epics actually proved out, not by building two now-superseded types just to make an old checklist green. See their own Post-implementation notes for the reasoning — that distinction ("ticket incomplete" vs. "spec drift from real implementation experience") is worth preserving, not collapsing into a flat done/not-done state.

## Post-v0.1 (added after real usage, outside the original build order)

20. [20-describe](20-describe/INDEX.md) — `ragctl describe`, read-only corpus visibility
42. [42-repo-graph-symbol-join](42-repo-graph-symbol-join/INDEX.md) — the repo-graph symbol join (scratch doc §14): a thin `SymbolProvider` interface, the join from a resolved call-site symbol to ragctl's exact-version evidence, a real `go/packages`-based Go provider, and the `explain_call_site` MCP tool exposing it. Pulled forward from `backlog/` and shipped in one pass after a 2026-09 competitive review independently reaffirmed the same design. Since live-verified — see the epic's own `INDEX.md`.
47. [47-continuous-verification](47-continuous-verification/INDEX.md) — a CI-runnable live MCP-over-stdio smoke test (`VERIFY-001`) and a mechanical MCP-tool-surface docs-drift check (`VERIFY-002`), added after a 2026-09 design review found the same failure shape twice: a real bug that every unit test missed and only a manual live-test session ever caught. `VERIFY-002`'s first real run immediately found two genuine, pre-existing doc bugs.
22. [22-orphan-lifecycle-gc](22-orphan-lifecycle-gc/INDEX.md) — a second, independent GC eligibility path (`ragctl gc --orphans`) for generations that failed mid-build or got stuck non-terminal, never promoted, and so invisible to the existing reference-based `ragctl gc` (epic 16). Generation-ID-scoped deletion throughout (never dependency+version-scoped, unlike epic 16's path) — unsafe otherwise, since a healthy retried generation can share a dependency+version with a failed earlier attempt. Pulled forward from `planned/` and shipped in one pass after a 2026-09 design review flagged it as a real, untouched resource-leak gap.
45. [45-competitive-validation](45-competitive-validation/INDEX.md) — deterministic, in-repo tests proving (not just claiming) ragctl's core lifecycle guarantees: atomic promotion never displaced by a failed candidate (`VALID-001`), structural cross-project version isolation (`VALID-002`), a measured JIT-sync latency benchmark (`VALID-003`), and a private-dependency fixture with a real API break (`VALID-004`) — which found and fixed a genuine, previously-undiscovered bug in `internal/normalize/godoc` (package-level constructor functions like `NewFoo()`/`Connect()` were never indexed at all). `POS-001` corrected README's positioning language. Pulled forward from `backlog/` after the same 2026-09 design review that flagged epic 22, as the single highest-priority gap in the system.
48. [48-generation-lifecycle-consistency](48-generation-lifecycle-consistency/INDEX.md) — two small fixes VALID-001 recommended as follow-ups: `FIX-001` makes a `Replicate`-stage failure transition `Generation.State` to `FAILED`, matching `Build`-stage failures. `FIX-002` makes `searchProject` check that a project's *specific resolved version* was itself promoted, not just that some generation is active — its first implementation attempt broke VALID-002's multi-project isolation guarantee, caught by the existing test suite and corrected; see its own post-implementation note.
50. [50-go-monorepo-workspace-resolution](50-go-monorepo-workspace-resolution/INDEX.md) — `MONO-001`: `ragctl scan`'s Go resolver now falls back to a synthesized `go.work` covering every `go.mod` in a repo when a submodule's own `replace` directives don't fully cover its siblings (the shape `hashicorp/terraform`'s per-backend submodules produce). Found live by [STRESS-001](../planned/49-full-loop-stress-testing/STRESS-001-real-dependency-heavy-project-scan.md); all 11 of terraform's discovered Go projects now resolve, not just the root.
